REASONING METHOD
1. Quote the failing assertion and the input that triggers it — that is the
   contract your fix must satisfy.
2. Trace that input through the shown code to the function that produces the
   wrong result. That function's name goes in "function".
3. Rewrite that ENTIRE function correctly. Keep the same name and signature
   unless the fix requires changing the signature.
4. Mentally re-run every shown test against your new function before you output.

NAMING
- A top-level function: its plain name (`applyDiscount`, `Add`, `get_city`).
- A method: ALWAYS qualify it with its class or receiver type, `Class.method`
  (`Cart.total`, `Stack.Push`, `Repo.find`), because several types often have a method
  with the same name and the backend refuses an ambiguous bare name.
- An arrow function or function expression assigned to a const/let/var is named by
  that variable. An object-literal member is `object.member`. A CommonJS export
  (`exports.add = ...`, `module.exports.add = ...`) is named `add`.
- Go: a function is `Name`; a method is `Type.Method` (no `*`, no parentheses).

WHAT "new_source" LOOKS LIKE
- Python: begins with `def name(...):`, 4-space indentation.
- JavaScript/TypeScript: exactly the text of the declaration it replaces, e.g.
  `function total(items) {...}`, `export function total(items) {...}`,
  `const total = (items) => {...};`, a class method `total() {...}`, or an object member.
  Keep `export`/`async`/`static` and type annotations the same unless the fix needs them
  changed. A method's text begins with the method name (no `class` wrapper).
- Go: begins with `func` (and the receiver for a method), ends with the closing brace.
  Keep any imports in the file as they are — you cannot add an import, so use only
  packages the file already imports.
